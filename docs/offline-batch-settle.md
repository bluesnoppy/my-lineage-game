# 離線結算加速：把快轉段的「逐隻發獎」換成「整段一次算完」

> ## ⚠️ 狀態：**草稿・尚未實作**（2026-07-30 擬，2026-07-31 補註）
> 這份寫的是**還沒做的設計**，不是現況。離線掛機現在怎麼運作看 `docs/offline.md`。
>
> **2026-07-31 補註——優先順序已經降低，動手前先讀這段：**
> 這份設計成立的前提是「結算慢是因為要逐隻發獎」。但後來查出玩家回報的那個 30 分鐘案例，
> 主因是**離線期間打到 NPC 血盟群戰**（場上持續是玩家型 NPC＝完整職業對戰，且會讓快轉退回全模擬），
> 而不是發獎管線本身。同一台裝置、同職業、同地圖，沒群戰的角色每事件 0.05 ms、有群戰的 5.58 ms。
>
> 所以：**先處理群戰那條**（成本直接歸零），這份批次結算是「之後想把一般結算再壓一個數量級」時才做。
> 而且 §4 已經寫明無法保證能到 30 倍——真要做，第一件事是量出「取樣段以外還剩多少」。

---

## 1. 目標與非目標

**目標**
- 結算耗時**不再跟擊殺數成正比**。同一隻角色掛 1 小時和 24 小時，結算時間應該差不多。
- 收益（經驗／金錢／掉落，含超稀有物）在**統計上與現在的逐隻重演等價**。不是打折、不是取平均。

**非目標**
- 不做「第二套結算」讓玩家選。只有一套，玩家不必也不能挑收益比較好的那個。
- 不追求「跟某一次重演的結果完全一樣」——重演本來就每次不同（RNG）。要求的是**同分布**。

## 2. 現況：留什麼、換什麼

**全部留著、一行都不用動：**
- 5 分鐘真實取樣（量殺速、消耗率、BOSS 實測）
- 統計快取 `player._offStats`（同圖同等級同裝備 72 小時內免取樣）
- 撞死即停、分段檢查點、落點還原
- 攀登／遺忘之島／軍王之室的特殊處理
- 升級重取樣、消耗品斷貨重取樣、BOSS 抽驗
- 離線紀錄格式（新增欄位即可，不破壞舊紀錄）

**只換一塊：** `fastEventStep()` 目前是「一個事件殺一批、走一次真實獎勵管線」。
改成「**一段時間一次算完這段的所有獎勵**」。

## 3. 核心作法

### 3.1 分段
把離線時間切成若干「穩態段」。**段之內**戰力、隊伍、消耗品、任務狀態都不變 → 可以一次算完。
**段的邊界**＝任何會讓上述前提失效的事件（見 §6）。

每一段的流程：
```
取樣（真跑 T 拍，量出這段的速率）
  ↓
外推（用二項抽樣一次算完剩下的 D 拍）
  ↓
檢查是否該切段 → 是就回到取樣，否則繼續
```
取樣那段是真跑的，所以出怪節流、AOE 批次、BOSS 處理全都自然正確。

### 3.2 從取樣推「各怪種殺了幾隻」
取樣期間直接記 `killTally`（現在就有）：`{怪名: 隻數}`。
外推時：
```
每拍擊殺數[怪種] = 取樣期間該怪種擊殺數 / 取樣拍數
這段的擊殺數[怪種] = 每拍擊殺數[怪種] × 這段拍數   → 再對小數部分擲一次骰
```

> **為什麼這樣就不會重蹈 2026-07-08 的覆轍**（繞過出怪節流 → 長老之室收益偏高 13%）：
> 因為擊殺率是**從真跑的取樣量出來的**，出怪延遲、節流、後排格、席琳與日光加速的效果
> 已經全部含在那個數字裡。跟當年「spawnMob(0) 連續出怪」憑空生怪是完全不同的做法。

### 3.3 掉落：對每個（怪種 × 掉落項）算一次二項抽樣
現行程式（`js/05-kill-progression.js` killMob 末段）對每一隻怪跑：
```js
dropList = MOB_DROPS[mob.n]                       // [[itemId, 機率%], ...]
每項: p = partyDropRate(ratePct × _dropBase × _clMult × _relicX2 / 100)
      if (Math.random() < p) gainItem(itemId, 1)
```
改成：對「這段殺了 N 隻的某怪種」的每一項掉落，
```
掉落數 = Binomial(N, p)        // N 次獨立試驗中成功幾次
for (i = 0; i < 掉落數; i++) gainItem(itemId, 1)   // 仍走原作 gainItem，祝福/強化/潘朵拉照原樣
```

**這在統計上與擲 N 次完全等價**，不是近似。所以：
- 0.001% 的金卡在 26,500 隻裡期望 0.24 張 → 約 24% 機率真的掉一張。**超稀有物該有的機會一點沒少。**
- 常見物的量與變異也都對。

`p` 的各個乘數怎麼取（全部執行期讀，不寫死任何數字 → 作者改平衡自動跟上）：

| 乘數 | 來源 | 段內是否固定 |
|---|---|---|
| `ratePct` | `MOB_DROPS[怪名]` | 是 |
| `_dropBase` | 恩賜怪 ×10／席琳 ×3（瘋狂 ×5）／一般 ×1 | **否**——是每隻怪的旗標 → 見下 |
| `classicDropMult()` | 模式 | 是 |
| `partyRewardMult()` | 隊伍人數 | 是（傭兵倒下會變 → 切段） |
| `_relicX2` | 裝備 `relicDropX2` | 是 |
| `trialItemDropMult` | 現行恆 1 | 是 |

**恩賜怪／席琳怪**：取樣期間分開記三種 tally（一般／席琳／瘋狂／恩賜），外推時各自用各自的倍率算。
它們的出現率也是從取樣量到的，不必知道規則。

### 3.4 卡片
`rollCardDrops` 對每隻怪擲三次（普 0.1%／銀 0.01%／金 0.001%，都乘 `partyDropRate`）。
同樣改成三次二項抽樣，然後呼叫原作 `acquireCard(name, tier, 1)` 該次數
（圖鑑未開通→自動登錄、已開通→實體卡，行為與原作一致）。

### 3.5 經驗與金錢
線性可加，直接乘：`取樣期間總量 / 取樣拍數 × 這段拍數`。
⚠️ 但**升級會改變殺速也會改變經驗需求** → 升級必須切段（§6）。

### 3.6 其他每殺一隻會做的事
| 項目 | 處理 |
|---|---|
| 傭兵經驗 | 線性，照擊殺數一次加總（要確認原作有沒有等級門檻造成非線性） |
| 寵物誘捕 `petCaptureOnKill` | 機率型 → 二項抽樣後呼叫原函式 |
| 收集冊／圖鑑登錄 | 由 `gainItem`／`acquireCard` 自然帶到，不另外處理 |
| 四大龍幼龍蛋 10% | 二項抽樣（BOSS 少，其實逐隻算也不貴） |
| 炎魔友好度（魔族神殿每殺 +1） | 直接加擊殺數 |
| 攻城／白目玩家掉落 | 這些地圖／情境**不走外推**（§7） |

## 4. 成本估計

現在：成本 ∝ 擊殺數（他 95 分鐘 26,500 隻 → 156.7 秒）。
改後：成本 ∝ **段數 × (取樣拍數 + 怪種數 × 掉落項數)** ＋ 實際掉落件數 × `gainItem`。

以他那筆估：段數個位數、每段取樣 3,000 拍、怪種 3 種 × 各約 20 項掉落 → 外推計算本身幾乎免費。
**剩下的主成本會變成「實際掉了幾件東西就要呼叫幾次 gainItem」**——他 95 分鐘掉了約 2 萬件，
這條省不掉（東西真的要進背包）。但 `gainItem` 比「整場戰鬥」便宜一個數量級以上。

> ⚠️ 老實說：**我沒辦法保證最後會快 30 倍**。取樣段是真跑的，段數越多越接近現況。
> 實作到能量的時候第一件事就是量這個，如果只快 3~5 倍，要不要繼續是你的決定。

## 5. 自我對帳（安全網）

取樣段是真跑的 → 我們同時有「實際結果」和「模型會怎麼預測這段」。
每次取樣結束時比對兩者（經驗／金錢／總掉落件數）：

- 落在合理誤差內 → 進外推
- 差太多 → 代表我們讀錯了掉落表或有沒考慮到的乘數（例如作者改了結構）→ **這次結算整段退回逐隻重演**，並在離線紀錄記一個原因碼

這樣就算哪天上游改版把我們的假設打破，也是**安全地壞**（變慢），不會默默少給或多給玩家東西。

誤差門檻先抓寬（例如 ±25%，避免 RNG 誤判），實測後再收。

## 6. 一定要切段的情況

| 事件 | 為什麼 |
|---|---|
| 升級 | 戰力變 → 殺速變；經驗需求也變 |
| 消耗品耗盡且補不到貨 | 戰局質變（現行已有這個判斷，沿用） |
| 傭兵倒下／歸隊 | `partyRewardMult` 變 → 所有掉率變 |
| 試煉道具達標 | `trialDropBlocked` 會從「可掉」翻成「不掉」 |
| 換圖（軍王鑰匙用完被傳回村等） | 怪種完全不同 |

段的長度也要設上限（例如每段最多 1 小時遊戲時間），避免長段累積誤差。

---

## 7. 一定要退回逐隻重演的情況

| 情況 | 為什麼 |
|---|---|
| 取樣期間血量掉破安全線 | 可能會死；外推算不出「第幾分鐘死」，而撞死即停不能失真 |
| 卡瑞（龍之谷地監6樓） | 1% 出現、殺了掉屠龍劍**並吃掉四樣任務道具**，而那四樣又要從別的怪掉回來——回饋迴圈，一次算完會失真 |
| 攻城區、PVP 競技場、白目玩家追殺中 | 有對手狀態、不是穩態刷怪 |
| 攀登、遺忘之島途中、時空裂痕 | 本來就不走快轉 |
| 軍王之室 | 內容就是 BOSS 對打，沒有可省的小怪 farming（現行已排除） |
| 取樣擊殺數太少 | 樣本不可信（現行已有此判斷） |
| 自我對帳沒過 | 見 §5 |

BOSS 一律維持現行做法（首打真模擬、之後按實測耗時推進、5% 抽驗）——BOSS 數量少，不是成本大宗。

## 8. 風險

1. **靜默失真**——最該怕的。掉落算錯不會噴錯，只會讓玩家默默少拿或多拿。
   對策：§5 自我對帳 ＋ 上線前的大樣本 A/B（見 §9）。
2. **我對掉落管線的理解有漏**。killMob 裡除了主掉落表，還有精通之證、四種職業試煉條件掉落、
   幼龍蛋、攻城攜帶物…等一堆特例。**實作時要逐行對過一遍**，不能只看主迴圈。
3. **上游改版**。掉落結構若變動，對帳會擋下來（退回重演），但要有人注意到紀錄裡的原因碼。
4. **段數失控**。如果某角色一直升級／一直斷貨，會退化成幾乎全程取樣＝現況。可接受（不會更慢），
   但要在紀錄裡記段數，才知道有沒有發生。

## 9. 驗證計畫（動手前先講好怎麼算過關）

1. **等價性 A/B**：同一份存檔、同一張圖、各跑 20 輪 24 小時（新舊各 10 輪），比對
   經驗／金錢／各物品件數的**平均與變異**。因為有 RNG，單輪比對沒意義——要看分布。
   - 過關標準：平均差 < 3%，且稀有物（出現率 < 1%）的總量差 < 15%
2. **超稀有物專項**：用一個掉率 0.001% 的物品，跑 50 輪，確認新舊「至少掉一件的輪數比例」接近。
3. **效能**：同一份存檔量新舊耗時，記錄段數。
4. **不變式**：撞死即停、消耗品耗盡、升級、鑰匙用完回村，各測一次行為沒變。
5. 用 `.testdata/` 的三份真實存檔（Lv97 法師 / Lv49 騎士 / Lv50 王族，含 74.8 KB 血盟、3,488 件倉庫）都跑一次。

## 10. 分階段實作

| 階段 | 內容 | 可獨立驗證 |
|---|---|---|
| 1 | 先只把**主掉落表**改成二項抽樣，其餘（卡片、經驗、金錢、特例）維持逐隻 | 是（A/B 只看主掉落） |
| 2 | 卡片、經驗、金錢加入外推 | 是 |
| 3 | 切段邏輯 + 自我對帳 | 是 |
| 4 | 特例逐項處理／退回清單收斂 | 是 |

每階段都能單獨 A/B、單獨上線。中途覺得不划算隨時可以停在任一階段。

## 11. 還沒確定、實作時要先查清楚的

- `gainItem` 每次呼叫的實際成本（如果它本身很貴，省下戰鬥也有限）
- 傭兵經驗是不是真的線性（有沒有等級門檻）
- `trialDropBlocked` / `trialForced100` 的完整條件
- 恩賜怪／席琳怪的旗標怎麼在取樣時分開統計
- 二項抽樣在 N 很大、p 很小時的實作（直接迴圈 N 次就沒意義了，要用泊松近似或反轉法；
  但要注意近似會不會影響超稀有物的正確性——這點要實測驗證，不能只信公式）
